# 一括処理と App モードの再設計（2026-11-01・決定版 v1）

本番確認で出た指摘（メモ 17・24・25・28・33）をもとに、「一括処理をどこから・どう扱うか」「App とキャンバスの役割」「向きごとの写真の扱い」を整理し、ユーザーと合意した内容。計画（`planTasks`）・サーバー・ジョブの仕組みは変えず、「どこで入れて、どこで押すか」「ノードが何を持つか」を変える。

## 1. 役割分担（決定）

- **キャンバス** = 構成を組む・設定する・試す場所（対話実行）。
- **App** = データを入れて一括で回す・結果を見る場所。
- **App = App 化したグループ**。入口ノードがあるだけでは App にならない。
  - 入口が無いグループ → 生成 App（今の CapsuleView のまま）。
  - 入口が 1 つ → 一括 App（左に写真の一覧、右に結果と履歴。範囲はグループの中だけ）。
  - 入口が 2 つ以上 → グループに「入口は 1 つにしてください」と注意。一括 App としては動かない。
  - **一括 App の結果は 1 種類（2026-11-02 決定）**。画像だけなら枝分かれしてよい（結果の画面は枝ごとの列、書き出しは枝ごとのフォルダ）。動画は写真 1 枚につき 1 本（ショットが複数なら Video Merge でまとめる）。画像と動画の両方ができる構成・動画が 2 本以上できる構成は、グループの上と App の画面に注意を出して動かさない（App 化のボタンも断る）。入口の無い生成 App は従来どおり並列の生成を断る。Batch Input は「つながれた流れ全体を写真 1 枚ずつ繰り返す入口」であり、枝分かれはその 1 回分の流れの形（別の軸）。
  - グループはいくつでも置けるが、App にできるのは 1 キャンバスに 1 つ（別のグループを App 化すると前のグループは外れる）。Apps 一覧と履歴はワークフロー単位のまま（2026-11-02 ユーザー判断: 複数 App はやらない）。
  - 互換: App 化したグループが無く入口ノードがある既存ワークフローは、キャンバス全体を 1 つの一括 App とみなす（救済）。テンプレートとチャットは最初からグループ＋App 化済みで組む。
- 保存の単位はジョブのまま。見せ方は「処理 / 履歴 / 結果」（2026-10-04 の方針どおり）。App の写真はワークフローに書かない（チーム共有 App を複数人が使うため）。

## 2. 入口ノード（決定）

- 入口ノードは **Batch Input だけ**。位置づけは「つながれたノード全てで繰り返す入口」（List ノードは直結の 1 ノードだけを繰り返す）。
- Batch Input が持つのは **試し用の ★ 1 件**（キャンバスの対話実行で流す写真）と SKU の規則。写真の一覧と「一括実行…」ボタンはノードから外し、App の左の入力欄に一本化する。
- 繰り返しの単位は写真 1 枚 = 1 件。下流の AI 処理（Remove Background / Image Generation / Try-On / Video Generation / Video Merge）が写真ごとに動き、参照画像や Model ノードの固定画像は全件で共通。Product Layout / Export は結果画面の側で写真ごとに適用。
- Try-On の繰り返し側は配線で決まる（Batch Input につないだ側が写真ごと、参照 / Model 側は共通）。服 n 枚 × モデル 1 も、モデル n 人 × 服 1 着 も作れる。
- **Cut Set Input と旧 Product Video ノードは廃止**（既存のワークフローはユーザーが削除する前提。読み込み時の展開も外す）。**動画の一括処理（SKU カードで何件も回す仕組み・kind 'video' のジョブ投入）も廃止**。過去の結果は履歴・ライブラリで見られるまま。

## 3. 向きごとの写真（決定）

- **参照画像ノードに「向き」の設定**を付ける: なし / 正面 / 右側面 / 左側面 / 背面 / ディテール / 全身。「画像を追加」のモデルタブから入れたときは自動で入る（今の `role`）。
- 多角度の動画は「向きつきの参照画像 ＋ ショットごとの Video Generation ＋ Video Merge」で組む。商品ごとに写真を入れ替えて対話実行で作る。
- Video Generation は、始点・終点につないだ画像の向きから「正面 → 右側面」の表示と「回転の指示文を入れる」ボタンを出す（今のまま）。
- **Kling v3 Pro の人物参照（elements）は自動**: そのショットと、同じ Video Merge につながる兄弟ショットの始点・終点にある向きつき参照画像を集め、正面 1 枚＋別角度（右側面 → 左側面 → 背面 → 全身 → ディテールの順）最大 3 枚を渡す。正面が無ければ付けない。Video Merge の無い単発ショットは自分の始点・終点だけが候補。ノードには「参照 n 枚（自動）」と 1 行だけ出す（Kling v3 Pro 以外では出さない）。Cut Set Input の「カット一式」ポートと Video Generation の「参照カット一式」入力は廃止。
- Model ノード（ライブラリのモデル・向きごとのポート）は今のまま。
- Export の `{sku}`: 入口ノードが無い構成では Export に「商品名」の欄を置いてそれを使う（空ならワークフロー名）。

## 4. テンプレート（決定）

- 商品動画（EC 標準 / ターンテーブル / ショート）: 参照画像（向きつき）× 必要な向き ＋ Text Prompt ＋ Video Generation × ショット ＋ Video Merge ＋ Export。
- 試着 → ターンテーブル: 参照画像（服・向きつき）× 4 ＋ Model ＋ Try-On × 4 ＋ Video Generation × 4 ＋ Merge ＋ Export。
- 商品写真の背景処理 / 商品写真から着用画像: Batch Input を入口にしたグループを App 化済みで組む。
- チャットのカタログから Cut Set Input を外し、参照画像に「向き」の設定を足す。

## 5. Batch Results ノード（決定）

- 新しくは置かず、キャンバスには「App で結果を見る」への誘導だけを置く（既存のキャンバスに置いてあるものは動かし続ける）。一括の結果の出口は App（と履歴・ライブラリ・Export）に揃える。
- キャンバスでの試し生成（★ の 1 件を各ノードの「実行」で流す対話実行）はそのまま。結果はキャンバスの結果ノードに出て、生成履歴とライブラリにも残る。

## 6. 保留・別途

- 服登録ノード（種類ごとの枠・メモ 38）: 向きごとの写真と同じ「枠ごとの画像」の発想。別途。
- 多角度の一括試着（一式を受けて向きの分だけ繰り返す List ノード型）: 必要になったら。

## 7. 実装の段階（案）

| 段階 | 内容 | 主な変更 |
|---|---|---|
| 1 | 参照画像の「向き」設定・Kling 参照一式の自動化・Cut Set Input / 旧 Product Video / 動画一括の廃止・テンプレート/チャットの組み直し | ReferenceImageNode・VideoGenerationNode・`plan.ts`（elements の集め方・cutSetInput 分岐の削除・shotsFromCanvas 廃止）・templates・agent catalog・App の video 種別の削除・Export の商品名 |
| 2 | Batch Input から一覧とボタンを外し ★ 1 件に。App の左の入力欄に一本化（既存の写真一覧は初回に App の初期値へ） | BatchInputNode・AppBatchInput・BatchSubmitDialog・会員向け説明 |
| 3 | App = App 化したグループ。グループに入口 1 つで一括 App、無ければ生成 App。Apps 一覧と履歴をグループ単位に。救済（グループ無し）を残す | appKind・AppsPage・CanvasPage の App モード・BatchAppView（グループの範囲で計画）・ジョブの写し（グループの範囲） |
| 4 | 「対象 / 対象外」の注意を App の「処理内容」にまとめ、ノードは印だけ | 各 AI ノード・App 上部 |

- 計画の純関数・サーバー・テストの大半は変わらない（cutSetInput / video ジョブ関連のテストは削除）。
