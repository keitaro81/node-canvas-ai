## 1. 目的

登録したモデル（人物）に商品（服）を着せた「着用カット」を AI で作る。モデルはあくまで着せ替え（試着）用（2026-10-31 の方針）。
用途は 2 つ。

1. **EC 用の着用画像**: 商品写真（平置き・ゴーストマネキン・トルソー）から、モデル着用の 1 枚を作る。商品 50 点 → 50 枚を一括で。
2. **商品動画の入力**: 着用カット（正面・側面・背面）を Cut Set の役割カットとして Video Generation に渡し、撮影なしで商品動画を作る。

## 2. エンジン（2026-10-31 時点の fal・調査済み）

- 側面・背面: 試着モデルは正面向きが前提。側面・背面の着用カットは「モデルの側面/背面カット × 同じ服の写真」で作れるかを試作で確かめる（服の背面写真があればそれを使う）。
- 進め方は商品動画と同じ: **試作で比較してから決める**。同じモデル写真 + 商品写真 2〜3 点で FASHN v1.6 / image-apps-v2 / Nano Banana 2 を並べる（1 組 約 $0.15、全体で $1 以内）。

## 3. モデルに必要なカット（再検討）

- 役割は「向き」だけにする: **正面（必須）/ 右側面 / 左側面 / 背面**。ディテールと全身はモデルには不要（商品動画の流用だった）。
- 既存の登録データは保持。モデル登録ダイアログは 4 役割の枠にし、ディテール・全身は「入っていれば表示（任意）」。
- 身長・サイズの数値は AI に効かない。試着エンジンはモデル写真そのものの体型に服を合わせるので、数値欄は作らない。着こなし（タックイン等）は FLUX VTO だけプロンプトで指示できる。

## 4. ノード設計（キャンバス = 配線の原則を守る）

### 4.1 Try-On ノード（新規・「画像」メニュー）

- 入力: **モデル画像**（image。Reference Image / Cut Set Input の役割ポート / ライブラリのモデルから）、**服の画像**（image。Batch Input の写真 / Remove Background の切り抜き / Reference Image）。
- 設定: エンジン（試作で決めた既定）、服の種類（自動 / トップス / ボトムス / ワンピース）、服の写真の種類（自動 / 着用 / 平置き・ゴーストマネキン）、品質。
- ノード内に「モデル」ボタン: ライブラリのモデルと役割（正面など）を選ぶと、そのカットがモデル画像になる（配線なしで使える。選んだ素材の参照をノードに保存）。
- 出力: 着用画像（image）。対話実行で 1 枚 → Image Display に出し、生成履歴とライブラリの生成画像に入る。

### 4.2 一括実行

- Batch Input の商品写真（服）ごとに試着 1 回（タスク種別 `tryon`・AI 段 1 つ）。モデル画像はジョブで固定（ノードに保存した素材の参照をサーバーが署名して渡す）。
- 結果は「生成結果」の列として確認グリッド・一括結果ノード・ライブラリのフォルダに出る（既存の imageEdit と同じ扱い）。Export の命名・ZIP も既存のまま。
- **動画への連結**: Try-On（正面）→ Video Generation → Video Merge は 2 段の制限に収まる（結合は数えない）。側面・背面の Try-On を並べれば、Video Generation の始点・終点に「役割」を持たせられる（Try-On ノードの「モデルの役割」から導く）。これで「商品写真 → 着用カット → 商品動画」が 1 つのワークフロー・1 回の一括実行で通る。

### 4.3 App

- 既存の撮影後工程 App（写真を入れる）がそのまま使える。モデルはキャンバスの Try-On ノードで決めておく（App 側で切り替えたい場合は後続で「モデルを選ぶ」欄を足す）。

## 7. 2b-1 試作の結果と推奨（2026-11-01）

**素材**: ライブラリ登録モデル A の正面・右側面・背面カット、服 = レザージャケットの平置き写真（一括処理の入力から）、カーディガンの着用写真（別人のモデルが着た写真）、SKU 61181209462 の右側面・背面の着用カット（商品動画ジョブの cuts）。fal を直接呼ぶ試作スクリプト（scratchpad・日をまたぐと消える）・合計 14 枚・約 $0.68。比較シート 3 枚をユーザーに送付。

|---|---|---|---|---|---|---|
| **Nano Banana 2 edit**（2K）＋試着用の厳格プロンプト | ◎ 形・質感・ディテールが忠実 | ◎ 色も形も忠実。モデル自身のインナー・ボトム・腕の位置を保持 | ◎ 右側面・背面とも成立（同じ向きの服写真を渡す） | 顔・髪・ポーズ・小物・背景を保持。構図が少し寄ることがある | 1792×2400 | $0.039 |

**分かったこと**
- 汎用の編集モデル（Nano Banana 2・image-apps-v2）は「2 枚目の服だけ」と明示しないと、着用写真の人物のポーズ・インナー・ボトム・バッグまで写し取る。Nano Banana 2 は「2 枚目の服だけを着せ、それ以外（人物・ポーズ・手・インナー・ボトム・靴・バッグ）は出さない。1 枚目はそのまま」と書いた**厳格プロンプトで解消**した（カーディガン・背面の 2 枚で確認）。
- FASHN は人物を画素ごと固定するので事故は無いが、色の再現が弱く解像度も低い（EC では色の正確さが重要）。
- 側面・背面は「モデルの同じ向きのカット × 服の同じ向きの写真」で Nano Banana 2・FASHN とも成立する。

**推奨**
- **エンジンは Nano Banana 2 edit だけで作る**（既定の厳格プロンプトはノードが持ち、ユーザーは「服の説明・補足」（任意・日本語可 → any-llm で英訳して差し込む。例: ニットカーディガン／ジッパーを閉める）だけ書く）。allowlist・料金表・一括実行（imageEdit）に既にあるので、2b-2/2b-3 は既存の画像編集の経路に乗せられる。
- FASHN v1.6 は見送り。Nano Banana 2 で「服以外が変わる」事故が実運用で目立てば、代替エンジンとして後から足す（ノードの設定に「エンジン」欄を足すだけで済む構造にしておく）。image-apps-v2・FLUX VTO は採用しない。
- 注意: 汎用モデルなので事故がゼロではない（厳格プロンプトでは 2/2 成功、全体で 14 枚中の問題は素朴プロンプトの 3 枚のみ）。一括 50 枚では数枚のやり直しを見込み、確認グリッドの差し替え（既存）で対処する。

**2b-2 の設定欄（推奨に合わせて §4.1 を更新）**: 解像度（1K / 2K）＋服の説明・補足（任意）。側面・背面は「モデルの同じ向きのカット × 服の同じ向きの写真」を同じノードで作る（役割はノード内のモデル選択で決まる）。「エンジン」「服の種類」「服の写真の種類」「品質」は FASHN を足すまで出さない。

## 8. 2b-3 一括実行の実装メモ（2026-11-01）

- タスクの種別は新設せず **imageEdit のまま**（生成結果の列・書き出し・ライブラリのフォルダ・費用の注意がそのまま効く）。エンドポイントは `fal-ai/nano-banana-2/edit`、image_urls は [モデル, 服]。
- 参照 `asset`（固定の画像・全アイテム共通）を追加。モデル（ノードで選んだライブラリのカット）のほか、写真由来でない配線（Reference Image・対話実行の結果）も固定の画像として使えるので「同じ服をいろいろなモデルに」（Batch Input = モデル写真・服 = 固定）も組める。
- 固定の画像の権限はジョブ作成時に sign-media と同じ判定で確かめ（持ち主/チーム共有のライブラリ素材・自分がアップした画像・アクセスできる WF のメディア）、投入時に service role で署名する。
- 服の説明・補足（日本語）はジョブ作成時に英訳（動画の動きと同じ仕組み）。

## 9. 2b-4 動画への連結の実装メモ（2026-11-01）

- Try-On の結果が持つ「向き」（モデルのカットの向き）を前段の参照（dep）に載せ、Video Generation の始点・終点の向きとして使う。Cut Set Input の役割カットと同じく回転指示が自動で付く（対話実行・一括実行とも）。
- テンプレート 2 つ: 「商品写真から商品動画: 試着 → ターンテーブル 12 秒」（Cut Set Input（服）→ Try-On × 4 → VG × 4 → Merge → Export）と「商品写真から着用画像（一括）」（Batch Input → Try-On → Export）。Try-On には向きの予定（params.role）が付き、「モデル」でモデル名を押すとその向きが入り、他の Try-On にも向きごとに入る。
- 側面・背面の着用画像は同じ向きの服の写真から作る前提（Cut Set Input の役割カット）。正面の写真だけから側面・背面を作る案は品質が読めないため採らない。
- 残: Kling の参照カット一式（elements）は Cut Set Input のカットからしか作らない（Try-On の結果を elements にするのは今後）。試着の中間画像は動画ジョブの結果欄には出ない（統合ビューはフェーズ D 候補）。
