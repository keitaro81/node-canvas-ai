# メンバー向け説明資料（非エンジニア向け）

> 最終更新: 2026-07-05。社内メンバー・関係者への説明用。専門用語は最小限。
> 技術的な詳細は [engineer-handover.md](engineer-handover.md) を参照。

## このサービスは何か

AI で画像・動画を「**フロー図のように組み合わせて生成する**」ワークスペース。

- 例:「テキストを入力 → 画像を生成 → その画像から動画を作る」を、ノードをつなぐだけで組める
- Flora AI にインスパイアされたツール
- **企業向け（toB）**。特に**複数の支店を持つ会社**を想定した作りになっている

**現在の段階**: 実顧客への**ピロット（試験導入）が可能な状態**。チーム機能・支店ごとの利用枠・データ分離まで実装済みで本番稼働中。一般公開（GA）にはあと少し準備が残っている（末尾参照）。

## 画面構成

### ホーム画面
- **My Projects** — 自分のワークフロー一覧
- **Team** — 同じチーム（支店）のメンバーが共有したワークフロー一覧。誰が作ったかのバッジと絞り込みつき
- **Community** — 全ユーザーに公開されたワークフロー（閲覧・コピー可能）
- **History** — 過去の生成物一覧
- **Apps の「履歴」タブ**（URL は /jobs。ナビの項目ではなく Apps ページのタブ）— 撮影後工程の App で処理した分を、App をまたいで一覧する運用画面。見えるのは自分の分と、チームに共有（Team / Public）されたワークフローの分。チームの owner は全件。進捗・失敗数・本日の利用枚数が自動で更新される。行を開くとその App の結果画面に入り、行から「キャンセル／失敗分を再実行／削除」もできる（削除は実行した本人とオーナーのみ）。名前か SKU で検索できる。※内部的には 1 回の処理 = 1 件の「ジョブ」（batch_jobs）で、使う人の画面にはこの言葉を出さない（2026-10-04 決定）
- **結果を開くと確認グリッド** — 上のタブで列（「切り抜き」と各バリアント）を切り替え、1 列ずつ写真のカードが並ぶ（カードに元ファイル名とサイズ）。準備完了になった順にサムネイルが描かれる（保存して次回から再利用。透過部分は市松で表示）。処理中はグリッドの上に進み（処理中 n / m）とキャンセルが 1 行だけ出て、終わると消える。失敗した写真があるときだけ「n 枚が失敗しました」の行が出て、「失敗 n 枚だけ表示」と「失敗分をやり直す」ができる。削除は履歴のプルダウン横の「…」から。クリックで選択、ダブルクリックか Enter で拡大して元画像と比較（左右で写真、上下で列）。各カードのチェックボックスを入れると「チェックした n 枚を再度切り抜く」（エンジンや設定を変えて、その写真だけやり直し）と「チェックした n 枚をダウンロード」が出る。「すべて選択」「失敗を選択」「解除」あり。「レイアウト設定」で余白や背景を変更して全アイテムに再適用（再課金なし）。バリアント = 投入元ワークフローの Product Layout ノードで、ジョブ画面での追加・削除・変更はノードに書き戻され、キャンバス側の追加・削除もジョブに反映される。編集できるのは「そのワークフローを編集できる人」（所有者と、「チームのメンバーも編集できる」がオンのときの同じチームのメンバー）だけ。それ以外のメンバーは閲覧のみ（編集したい場合はワークフローをクローン）。「すべてダウンロード」でフル解像度の ZIP

- 左側のツールバーでノードを追加
- ヘッダー中央の **Canvas / App** トグルでモード切り替え

## ノードの種類

| ノード | 役割 |
|---|---|
| Text Prompt | プロンプト（指示文）を入力する |
| Prompt Enhancer | 入力テキストを AI が最適なプロンプトに書き換える |
| Reference Image | 参照画像をアップロードする |
| Reference Video | 参照動画をアップロードする |
| Image Generation | AI で画像を生成。参照画像を最大10枚同時使用可能 |
| Video Generation | AI で動画を生成。テキスト→動画・画像→動画・動画→動画に対応。Kling v3 Pro では「参照カット」（同じ人物・同じ服の別角度を複数枚つなぐと、動画全体で見え方を保つ）と「マルチショット」（ショットごとの動きと秒数を並べ、合計 3〜15 秒の 1 本にする）が使える。商品訴求動画の作り方は後述 |
| List | 複数の画像やテキストをまとめてバッチ処理に渡す |
| Camera List | カメラアングル（正面・俯瞰・斜め等）を複数指定してバッチ処理 |
| Note | キャンバス上のメモ。生成には関与しない |

生成ノードを実行すると「Image Display / Video Display」が自動で作られ、結果が表示される。

### 撮影後工程（商品写真の一括処理）
| ノード | 役割 |
|---|---|
| Batch Input | 商品写真を最大 50 枚まとめて登録（ファイル名から SKU を抽出）。★ の 1 枚だけをキャンバス上で試せる。「一括実行…」で全枚数を裏側の処理に投入する |
| Remove Background | 背景を切り抜く（BiRefNet v2 / Bria）。元画像のピクセルは変えず、マスクだけを保存する |
| Product Layout | 余白・配置・背景・影を指定して EC 用のレイアウトを作る。設定を変えても再課金なしで描き直せる |
| Batch Results | 一括結果。このワークフローから投入したジョブと、その確認グリッド（切り抜き・バリアント・生成結果）をキャンバス上で見る。チェック・拡大・再度切り抜く・書き出し・キャンセル/削除もここからできる |
| Export | ファイル名の規則・形式・容量上限を指定して ZIP に書き出す。「切り抜きの透過 PNG も書き出す」（既定でオン）で元のサイズの透過 PNG が `cutout/` に入る。動画だけをつないだときは形式・品質・最大サイズ・切り抜きの設定が出ず mp4 のまま。規則の中の置き換えに使えない `{…}` には警告（固定の文字は {} なしで書く。例 `商品動画_{sku}_{index:02}`）。アイテム情報が無いときの ZIP 名はワークフロー名（2026-11-01） |

始めた処理はブラウザを閉じても進み、App の結果欄か Apps ページの **履歴** タブから状態を確認できる。

## チーム機能（支店運用）

> ここが 4月時点から最も大きく変わった部分。**すでに本番で使える**。

- **チーム = 支店**。1人のユーザーは1つのチームに所属する。
- **役割**: オーナー（複数可）とメンバー。オーナーだけが、招待・メンバー削除・役割変更・チーム名変更をできる。
- **招待リンクで参加**: オーナーが「招待リンク」を発行して渡すと、相手はそれを開くだけで参加できる（リンクは7日間有効・1本のみ）。
  - すでにアカウントがある人 → リンクを開いて「参加する」
  - **アカウントがない人 → そのリンクからその場でアカウントを作ってそのまま参加**（招待経由でのみ新規登録できる）
- **共有**: ワークフローは「非公開 / チーム内共有 / 全体公開」から選べる。チーム内共有にすると同じ支店のメンバーが見られる。
- **使用状況**: チーム設定で、今月の画像・動画の使用量（枠に対する消費）とメンバーごとの内訳が見られる。

**運営の作業はシンプル**: 運営側は「支店のチームを作り、オーナーを1人登録する」だけ。以降のメンバー追加はオーナーが招待リンクで自分たちで行える。

## 生成の利用枠（クォータ）

- 既定: 画像 **100枚** / 動画 **7本**（チームごとに設定可能）
- **チーム（支店）単位の月次管理**。個人ごとではなく、**支店に割り当てた枠をメンバー全員で共有**する。
- 毎月自動でリセット。枠を使い切ると、その月はそれ以上生成できない。
- 上限チェックはサーバー側で行われるため、回避はできない。

## 現時点の制約

- **ページリロード中の生成**: 画像生成の途中でリロードすると結果が復元されないことがある（動画は数分以内なら復元可能）。
- **リアルタイム共同編集**: 未対応。同じワークフローを複数人が同時に編集することはできない（チーム内での共有・閲覧は可能）。
- **生成物は90日で自動削除**: 長期保存が必要なものはダウンロードしておく。

## チームでワークフローを一緒に編集する（チームの編集を許可）
- 表示範囲を Team か Public にしたうえで、表示範囲メニューの「チームのメンバーも編集できる」をオンにすると、同じチームの全員がそのワークフローを編集できる（カードに「編集可」バッジ）。オフ（既定）なら他のメンバーは閲覧とクローンだけ。
- 同時に編集できるのは 1 人ずつ。所有者は開けばすぐ編集でき、メンバーは「編集する」を押して編集を始める。誰かが編集中はヘッダーに「○○さんが編集中・閲覧のみ」と出て、その人の画面は閲覧になる（編集者が保存すると 20 秒以内に取り込まれる）。
- 編集中の人がタブを閉じる・別の画面へ移る・10 分操作しない・タブを 5 分隠したままにすると編集は自動で終わる。90 秒更新が無いときは「引き継ぐ」で引き継げる。
- 名前・表示範囲・編集の許可・削除は所有者だけ。編集中に他の人の保存とぶつかった場合は上書きせず、「読み直す」か「自分の変更をコピーとして保存」を選べる。
- 編集を許可したワークフローのジョブ（確認グリッド）では、編集できるメンバーもバリアントを変更できる（キャンバスを誰かが編集中のときは保存できない）。

## 規定プロファイル（設定一式の書き出し・読み込み）
- キャンバス左の Workflows 一覧で、開いているワークフローの「…」→「プロファイルを書き出す」で、撮影後工程の設定（SKU の抽出規則・切り抜き・バリアント一覧・背景生成・書き出し）を 1 つの JSON（`<名前>.ppprofile.json`）に書き出せる。
- 「プロファイルを読み込む…」で別のワークフローに当てられる。既存のノードは残して設定を更新し、バリアントは名前で突き合わせて「更新・追加・削除」、背景生成は Text Prompt ＋ Image Generation（ジョブごと）を作ってつなぐ。当てる前に内容の確認が出る。同じプロファイルなら同じ出力になる（2 社目以降の導入はプロファイルの編集だけで済ませる土台）。
- サンプル: リポジトリの `docs/profiles/sample-ec-sns.ppprofile.json`（EC 白背景 1200×1200 ＋ SNS ストーリー 1080×1920 の生成背景）。

## 生成した背景を使う（SNS 用バリアントなど）
- Text Prompt → Image Generation（パネルの「一括実行のスコープ」を「ジョブごと」に）→ Product Layout の背景入力につなぎ、Product Layout の「背景の種類」を「画像」にする。Image Generation の結果ノード（Result）から背景入力につないでもよい。
- 一括実行では背景の生成はジョブで 1 回だけ（50 枚でも 1 回。Nano Banana 2 で約 $0.04）で、全アイテムの同じバリアントに同じ背景が使われる。投入前の確認に「ジョブごと n 件」と出る。
- 背景入力につながっていない「ジョブごと」の Image Generation、アイテムごとのスコープの背景、プロンプト無しは一括実行の対象外（投入前に注意が出る）。
- キャンバス上の Product Layout のプレビューは、背景の Image Generation を **キャンバスで Generate したとき** に背景付きになる（それまでは単色で描き、その旨の案内が出る）。一括実行の結果（Batch Results / App / ジョブ管理）はジョブごとに生成した背景を使うので、Generate を押していなくても背景付きになる。

## Apps（App 化したワークフローの一覧）と App モード
- 左のナビの **Apps** に、App モードで使えるワークフローが並ぶ。自分のものと、チームに共有されたもの。種類は 2 つ:
  - **撮影後工程**（Batch Input があるワークフロー）: App モード = 左の「写真を追加」で写真を入れて「n 枚を処理する」、右の「結果」に確認グリッド。過去の分は「履歴」のプルダウン（日時・枚数・状態）で切り替える。
  - **生成**（グループを App 化したワークフロー）: 従来の App モード。
- カードをクリックすると `/app/<id>` が開く（カードに「App で開く」「キャンバス」のボタンは無い。ノードを見る・編集する人は My Projects からキャンバスを開くか、App 画面右上の Canvas 切替を使う）。カードには名前・種類・最終更新の相対表示（n分前 / n時間前 / n日前）だけを出す（誰のワークフローか・履歴の件数は出さない）。
- 撮影後工程 App で入れた写真は **その画面だけで持ち、ワークフローには保存しない**（共有 App を使うメンバーの写真がワークフローに混ざらない）。処理した分の結果は残る。SKU の規則はキャンバスの Batch Input ノードの設定に従う。
- 結果欄はキャンバスの現在の Product Layout / Export ノードの設定を見る（レイアウトを変えたい人はキャンバスで変える）。「再度切り抜く」「ダウンロード」もここからでき、処理中のキャンセルと失敗分のやり直しは状態があるときだけ上の行に出る。削除は履歴のプルダウン横の「…」。履歴のプルダウンには、チームの他の人が実行した分だけ名前が添えられる。
- **レイアウト設定は App の左サイドバー**（「写真を追加」の下）にある。キャンバスの Product Layout ノードをそのまま編集する形で、変えると右の結果にすぐ反映され、ワークフローに保存される。バリアントの追加・削除もここから（ノードの追加・削除になる）。変更できるのはキャンバスを編集できる人だけ（所有者と、編集を許可されたメンバーが「編集する」を押したとき）。
- Apps ページの「履歴」タブ（/jobs）は全 App の処理を横断して見る運用画面。各行に App 名が出て、行を開くとその App の結果として App モードで開く。元のワークフローが開けない分だけ、従来の詳細画面で開く。
- **使う人の画面の言葉**（2026-10-04 決定・Photoroom の分かりやすさに寄せる）: 「ジョブ」は出さず「結果」「履歴」「処理」、「投入」は「追加」「処理を始める」「送信」、「書き出し」は「ダウンロード」（キャンバスの Export ノードは従来どおり「書き出し」）。App からの処理には名前を付けず、日時と枚数で自動（キャンバスの Batch Input から実行するときだけ任意の名前を付けられる）。状態の表示は「送信中 → 待機中 → 処理中 → 完了 / 一部失敗 / キャンセル済み」。

## 一括結果ノード（キャンバスで処理の結果を見る）
- ノードメニューの「撮影後工程」から **Batch Results** を置くと、このワークフローから投入したジョブ（新しい順）が選べ、ジョブ管理画面と同じ確認グリッドがノードの中に出る。入出力ポートは無く、大きさはドラッグで変えられる。
- できること: 列タブの切替、カードのチェック、ダブルクリックで拡大、チェックした写真の「再度切り抜く」「ダウンロード」、すべてダウンロード、キャンセル・失敗分の再実行・削除、「App で開く」（その処理を App モードで開く）。
- **レイアウトはキャンバスの Product Layout ノードで変える**。余白や背景を変えると、ノード内のサムネイルがその場で描き直される（fal は呼ばない・再課金なし）。Product Layout ノードを足せばバリアントの列が増える。書き出しの形式や「切り抜きの透過 PNG も書き出す」はキャンバスの Export ノードの設定に従う。
- 見えるジョブはジョブ管理画面と同じ規則（自分が投入したもの。ワークフローがチームに共有されていればチームの投入分も）。
- キーボード操作はノードの中をクリックしてから（矢印キー・Space・Enter・B）。ノードの外ではキャンバスの操作に戻る。
- App モード（撮影後工程 App）では、同じ確認グリッドが右側の結果欄になる。

## AI 処理をつなげる（切り抜き → 合成 / レタッチ → 切り抜き）
- 線をノードの本体にドロップすると、同じ種類の**空いている次のポート**につながる（Try-On のモデルが入っていれば服へ、Video Generation の開始が入っていれば終了へ。全部埋まっていれば最初のポートを置き換える・2026-11-01）。ポートの名前はノードにマウスを載せると横に出る。線を伸ばして空いた場所で Try-On を出すときは、Model ノード / 参照画像からは「モデル」に、それ以外（Batch Input / Cut Set Input / 切り抜き / 生成結果）からは「服」につながる。
- 同じキャンバスに Batch Input と Cut Set Input の両方があるときは、一括実行は**押した入口の枝だけ**が対象になる（もう一方の枝は無視。ノードの「一括実行: 対象 / 対象外」も自分の入口で判定・2026-11-01）。
- 一括実行は、写真ごとの AI 処理を **1 経路につき 2 段まで** つなげられる（3 段目は投入前に注意が出て対象外）。
  - 切り抜き → 合成: Batch Input → Remove Background → Image Generation（切り抜いた商品だけを入力にして背景を生成・合成）。同じ Remove Background から Product Layout にもつなげる。
  - レタッチ → 切り抜き: Batch Input → Image Generation（レタッチ）→ Result → Remove Background → Product Layout。レタッチ後の写真を切り抜いてレイアウトする。
- Image Generation に写真由来の画像入力（Batch Input・Remove Background・前段の Image Generation）があれば、「一括実行のスコープ」の設定に関わらず写真ごとに実行される（ノード側でスコープが「アイテムごと」に固定される）。「ジョブごと」は画像入力の無い背景生成だけに使う。
- キャンバスでは Remove Background の出力を **Image Generation と Try-On の画像入力** につなげる（他のノードの画像入力にはつながらない）。Remove Background を「実行」すると透過の切り抜き画像も常に保存され（2026-11-01〜・つなぐ順番は関係ない）、Image Generation の「参照 1（切り抜き）」や Try-On の服になる。それより前の結果で透過画像が無いときは、Image Generation / Try-On の実行時にマスクと元画像からその場で作って保存する（「切り抜き画像を用意中…」と出る。fal は呼ばない）。
- 一括実行の確認ダイアログに **ノード別の内訳**（何が何回動くか・2 段なら段数）が出る。写真ごとの画像生成があるときは「枚数 × 種類 = 回数」の注意が必ず出る（生成は切り抜きより時間もコストもかかる。Nano Banana 2 の編集は 1 回 ≈ $0.04）。2 段の処理は、1 段目が終わった写真から順に 2 段目が投入される。
- ジョブ画面には **生成結果のタブ**（ノード名）が増える。レタッチ → 切り抜きのジョブでは「切り抜き」タブはレタッチ後の写真を切り抜いた結果で、拡大表示の「元画像と比較」は元の写真。
- 書き出しは生成結果も ZIP に入る（フォルダ名 = ノード名、ファイル名は `{sku}_{ノード名}_{index}`、形式は Export の指定に変換）。切り抜きの透過 PNG（元のサイズ・`cutout/{sku}_cutout_{index}.png`）は Export ノードの「切り抜きの透過 PNG も書き出す」が既定でオンなので一緒に入り、ジョブ画面の書き出しダイアログでも付け外しできる。「再度切り抜く」は切り抜きだけをやり直し、その切り抜きを入力にする生成は自動でやり直される（レタッチ → 切り抜きのジョブで、レタッチはやり直さない）。

## 商品訴求動画（EC 向け・2026-10-13〜）
- 目的: アイテムを着たモデルの短い動画で、シルエットや特徴を伝える（縦長・15 秒前後・無音ループ。参考 = EC サイトの商品ページ 1 枚目の動画）。
- 方針: **着用カットの写真から動かす**（登録モデルに商品を合成する方式より実物に忠実）。指先の細かい動き（ボタンを留める等）は AI が苦手なので使わない。
- 今できること（キャンバスの Video Generation ノード・モデル = Kling v3 Pro）:
  - **開始フレーム**（in-image）に主カット、**参照カット**（in-image-cuts）に同じ人物・同じ服の別角度を最大 4 枚つなぐ。ノードの中で「正面」を選ぶ（残りが別角度）。別人を混ぜると振り向いた顔がすり替わるので、同一人物だけにする。
  - **マルチショット**にショットごとの動き（例: ゆっくり正面を向く / 振り向く / 重心を移す）と秒数を並べると、合計がその動画の長さになる（3〜15 秒）。つないだプロンプトは共通の説明として各ショットの先頭に付く。
  - 開始フレームが無くても参照カットがあれば、その正面を開始フレームにして動かす。
- 試作（2026-10-13）: 5 カット × 3 秒を別々に生成して結合した 15 秒は、服の忠実さが高く動きも自然だった。

- **一括処理の結果は「フォルダ」でライブラリに（2026-10-31）**: 切り抜き・レイアウト・AI 処理の一括処理は、1 回の処理（ジョブ）が 1 つのフォルダのカード（中の画像が 3 枚重なった見た目・「一括処理 ・ n 枚」の印）になり、ライブラリの「生成画像」タブにキャンバスで生成した画像と日時順に混ざって並ぶ。クリックで中身のダイアログが開き、確認グリッドと同じ列（切り抜き / バリアント / 生成結果）をタブで切り替えて見られる（元の写真は含まない。結果が無い写真は出ない）。クリックで拡大、タイル右上でフル解像度をダウンロード、「結果の画面で開く」でジョブの画面へ。保持は処理の履歴と一緒で、削除は履歴から。「画像を追加」ダイアログの AI 画像生成にも同じフォルダが並び、クリックで中身が上に重なって開く。複数受ける入力（一括処理の入力など）では列をまたいで何枚でもチェックして「n 枚の画像を追加」、1 枚だけの入力（参照画像ノードや Capsule）では 1 枚だけ選んで「この画像を使う」（親のダイアログと同じ手順。ヘッダーの「戻る」で親に戻る）。切り抜きとバリアントの列はファイルとして保存されていないので、選んだときにその場でフル解像度を描いて処理の階層に保存する（「画像を用意しています（n / m）」。同じものは 2 回目から再利用）。商品動画は今までどおり SKU ごとの単独カード。

  - App の左「カットを入れる」: SKU ごとのカードに、ショットごとの枠組み（番号・役割・秒数の見出し）が並ぶ。終了カットのあるショットは「始点 │ → │ 終点」の 2 枠が横並び、無いショットは「始点」の 1 枠。同じ役割（例: 右側面）が複数のショットに出るときは 1 枚の写真を共有し、どの枠から入れても全部に入る（2 回目以降の枠には「ショット n と同じ写真」と出る）。カットが揃ったショットだけ番号に色が付き、揃っていないショットは飛ばす。枠のアイコンは人物のシルエット（正面 / 横顔 / 後ろ姿 / 襟元の寄り / 立ち姿）。正面がどのショットにも無い構成では「主カット」の枠が別に出る（必須）。構成で使わない役割は下の「補足カット（任意）」に「参照」の印付きで並び、動画の角度には使わず服の見え方を揃える参照にだけ使う。写真はドロップかクリックで入れる（ファイル名では判定しない）。同じ人物・同じ服のカットだけを入れる。入れた写真は「処理する」の後も残り、このブラウザに記憶されるので再読み込みしても戻る（別の端末には引き継がれない）。最初からやり直すときは「すべて外す」。 Cut Set Input ノードに入れた SKU と写真は、App モードの初期値になる（このブラウザの記憶が無いとき・2026-11-01）。入れる写真は、Video Generation に直接つなぐ商品動画では同じ人物が同じ服を着た写真、Try-On を経由する構成では服の写真（側面・背面は誰かが着た写真でよい）。SKU は商品の管理番号（1 つの商品 = 1 SKU）で、ファイル名・フォルダ名・結果の見出しに使う。
  - **終了カット（任意・2026-10-17）**: ショットの「→」の右で終了カットの役割を選ぶと、開始カットの写真から終了カットの写真へ到達する動きを AI が埋める（始点と終点が写真で決まるので、「正面 → 右側面」のように回る動きの到達点がぶれない）。「終了なし」のショットは開始カットの写真から動きの指示どおりに自由に動く。終了カットを指定したショットは、開始・終了の両方のカットがある SKU だけ作り、無ければそのショットを飛ばす。「ターンテーブル 12 秒」は 正面 → 右側面 → 背面 → 左側面 → 正面 の 4 区間（各 3 秒）で 1 周する（全身 4 方向のカットが必要）。作るショットが 1 本だけになった SKU は、そのショットの動画がそのまま結果になる。終了カットのあるショットは、始点と終点の組み合わせから回る向き・途中で見える姿・見せてはいけない姿の指示を自動で付ける（例: 右側面 → 背面なら「カメラから顔を背けて回り、正面は見せない」）。「動き」の欄は補足だけで、空でもよい。静止ショット用の定型文（「正面を向いて立ち、呼吸する」など）が残っていても無視するので、カスタムで役割だけ変えて回転を組んでも「正面を向け」と読まれない。
  - **プロンプトは日本語で OK（2026-10-17）**: ノードの「共通の説明」「避けたいこと」「動き」は日本語で書ける。処理を始めるときに裏で英語へ自動翻訳して AI に渡す（英語で書いた文はそのまま）。テンプレートの文も日本語で表示され、こちらは決まった英訳を使う。翻訳に失敗したときは処理を始めずにメッセージが出るので、少し待ってやり直す。
  - 「n 件を処理する」→ 確認（件数・動画ショット数・金額）→ 処理は裏側で進む。1 SKU につき 1 本、写真の比率のまま、無音。費用は 1 秒 $0.10（15 秒で約 $1.5 / SKU）。
  - 右「結果」: SKU ごとに結合済みの動画が再生され、ダウンロード（MP4）と「すべてダウンロード」（ZIP）ができる。結果欄に出るのは結合済みの動画だけで、ショット別の表示は無い（2026-11-01 決定）。失敗した SKU は「失敗分をやり直す」。作り直したいショットはキャンバスでその Video Generation を対話実行する。

- **空のキャンバスの案内**: New project で開いた空のキャンバスに「何を作りますか？」のカードが出る。「テンプレートから選ぶ」か「チャットで組む」で、ノードが組まれた状態から始められる（自分で組むときは左の「＋」か右クリック）。 カードの外をクリックするか ✕ で閉じられ、そのキャンバスでは再表示しない。ノードを全部消して空になったときは出ない（2026-11-01）。

- **チャットで組む**: 作りたいものを日本語で書く（例「商品写真の背景を白にして 1200×1200 で書き出したい」「服の正面と右側面の写真から回る商品動画を作りたい」）と、ノードをつないだ構成を提案する。提案はノードの一覧と接続の本数で表示され、「この構成で作る」（My Projects では新しいワークフロー・空のキャンバスではそのキャンバス）で組み上がる。曖昧なときは質問が返るので答える。構成は作ったあとで自由に組み替えられる。
  - 費用: LLM の利用分がダイアログに出る（1 往復 $0.02〜0.05 程度・Claude Sonnet）。画像や動画の生成はしない（組むだけ）。1 つの会話は 12 往復まで。
  - できること・限界: 用意しているノードの範囲で組む（存在しないノードや設定は使えない。配線の誤りは自動で 1 回直す）。Try-On のモデルは、構成に入る Model ノードで作ったあとに選ぶ。組まれたノードの名前は種類名のまま（Batch Input / Try-On / Video Generation …）で、チャットが付けた短い説明は構成一覧に添えるだけ。Remove Background は背景処理を求めたときだけ入り、試着や動画の前に自動では入らない（AI 処理が 2 段になるときは注意が出る）。
- **LLM の口の変更**: プロンプトの翻訳・Prompt Enhancer・チャットは fal の OpenRouter 経由（openrouter/router）で動く。以前の any-llm は fal で非推奨になったため予備にした。

## 試着（Try-On）— モデルに服を着せた着用画像（2026-11-01〜）

- **Try-On ノード（「画像」メニュー）**: 左の上のポートに「モデル」、左の下のポートに「服」をつなぐと（ポートはそれぞれの行の横にある・2026-11-01）、モデルがその服を着た画像を 1 枚作る（エンジンは Nano Banana 2・約 $0.04・画像の利用枠に数える）。モデルは **Model ノード**（「画像」メニュー。「モデルを選ぶ」でライブラリのモデルを選ぶと、正面 / 右側面 / 左側面 / 背面の行にサムネイルが入り、右の向きごとのポートからつなぐ。1 つの Model ノードから複数の Try-On につなげる）か、参照画像の「画像を追加」ダイアログの **モデル** タブ（モデルと向きを 1 つ選ぶ。向きも参照画像に記録され、動画の回転指示や試着の向きに使われる）からつなぐ。以前にノードの「モデル」ボタンで選んだモデルは、ノードに残っていればそのまま使える（✗ で外せる。Model ノードをつなぐと配線が優先）。服は商品写真（Reference Image / Batch Input の写真）・Image Display・Remove Background の切り抜きのどれでもよい。
- **向きを合わせる**: 服の写真と同じ向きのモデルを選ぶと、側面・背面の着用画像も作れる（モデルの右側面 × 服の右側面の着用写真、など）。
- **服の説明・補足（任意・日本語可）**: 「ニットカーディガン。ボタンは開けたまま」のように書くと生成時に英訳して使う。空でもよい（ノードが試着用の指示を持っている）。解像度は 1K / 2K。
- **結果**: Image Generation と同じく右に Image Display が作られてそこに出る。生成履歴とライブラリの「生成画像」にも入る。Try-On の出力ポートから次のノード（Video Generation など）へもつなげる。
- **モデル登録は 4 つの向きに**: ライブラリの「モデル」タブの登録・編集ダイアログは正面（必須）/ 右側面 / 左側面 / 背面の 4 枠になった（以前に入れたディテール・全身は残り、入っていれば表示される）。
- **一括実行（商品 50 点をまとめて）**: Batch Input の写真（服）を Try-On の「服」につなぎ、モデルは Model ノード（または参照画像のモデルタブ）から「モデル」につないでおく（ジョブの間は同じモデルで固定）。Batch Input の「一括実行…」で写真ごとに着用画像を 1 枚ずつ作る（1 枚 約 $0.04・画像の枚数の上限に数える）。結果は処理の画面に「Try-On（ノード名）」の列として並び、「すべてダウンロード」や Export の命名規則、ライブラリの「一括処理 ・ n 枚」のフォルダも切り抜き・生成結果と同じように使える。ノードには「一括実行: 対象（1 段目・写真ごとに 1 枚）」と出る。
  - 切り抜き → 試着（商品写真の背景を消してから着せる）、試着 → Video Generation（着用画像から動画）もつなげられる（AI 処理は 1 経路 2 段まで）。逆に、モデルの写真を Batch Input に入れて同じ服を固定（Reference Image）にすれば「同じ服をいろいろなモデルに」もできる。
  - 「服の説明・補足」の日本語は、ジョブを作るときにまとめて英訳される（動画の動きと同じ）。
  - 他の人のライブラリ素材など、自分が見られない画像を固定画像にしていると「固定の画像にアクセスできません」と止まる（モデルを選び直す）。
- **着用画像から商品動画（2b-4）**: Try-On の出力を Video Generation の開始・終了フレームにつなぐと、Try-On のモデルの向き（Model ノードのポート / モデルタブの向き）が引き継がれ、「正面 → 右側面」のように回転の指示文を入れられる（Cut Set Input の役割カットと同じ扱い。テンプレートのショットには最初から入っている）。
- **テンプレート「商品写真から商品動画: 試着 → ターンテーブル 12 秒」**: Cut Set Input（服のカット・SKU ごと・正面/右側面/背面/左側面）→ Try-On × 4 → Video Generation × 4 → Video Merge → Export が組まれた状態で始められる。ノードの名前は種類名のまま（Cut Set Input / Text Prompt / Model / Try-On / Video Generation / Video Merge / Export）で、向きは Try-On の「向きの予定」と Video Generation の「正面 → 右側面」の行に出る。作ったら「Model」ノードの「モデルを選ぶ」でモデルを選ぶ。向きごとのポートが 4 つの Try-On につながっているので 1 回で 4 つに入る（モデルにその向きのカットが無い Try-On は対象外になり、そのショットは飛ぶ）。ショットの「動き」「避けたいこと」には回転の定型文が最初から入っている。あとは Cut Set Input に服のカットを入れて「一括実行…」すると、SKU ごとに 試着 4 枚 → ショット 4 本 → 結合 が 1 回で進む（服の向きが足りない SKU はそのショットを飛ばして残りで 1 本）。
- **テンプレート「商品写真から着用画像（一括）」**: Batch Input（服の写真）＋ Model → Try-On → Export。「Model」ノードでモデルを選んで写真を入れれば、写真ごとの着用画像がまとめてできる。
- **注意**: 汎用の編集モデルなので、服以外が少し変わることがゼロではない（構図が少し寄るなど）。気になるときは作り直す。テンプレートの側面・背面の着用画像は、その向きの服の写真から作る（正面の写真だけから側面・背面を作るのではない）。
  - **結果欄は結合済み動画の再生とダウンロードだけ（2026-11-01 決定）**: ショット別の表示とショット単位のやり直しは無い。作り直したいショットは、キャンバスでその Video Generation を対話実行して作り直す。失敗した SKU 全体は「失敗分をやり直す」。
