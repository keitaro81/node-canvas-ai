# メンバー向け説明資料（非エンジニア向け）

> 最終更新: 2026-07-05。社内メンバー・関係者への説明用。専門用語は最小限。
> 技術的な詳細は [engineer-handover.md](engineer-handover.md) を参照。

## このサービスは何か

AI で画像・動画を「**フロー図のように組み合わせて生成する**」ワークスペース。

- 例:「テキストを入力 → 画像を生成 → その画像から動画を作る」を、ノードをつなぐだけで組める
- Flora AI にインスパイアされたツール
- **企業向け（toB）**。特に**複数の支店を持つ会社**を想定した作りになっている

**現在の段階**: 実顧客への**ピロット（試験導入）が可能な状態**。チーム機能・支店ごとの利用枠・データ分離まで実装済みで本番稼働中。一般公開（GA）にはあと少し準備が残っている（末尾参照）。

## 画面構成

### ホーム画面
- **My Projects** — 自分のワークフロー一覧
- **Team** — 同じチーム（支店）のメンバーが共有したワークフロー一覧。誰が作ったかのバッジと絞り込みつき
- **Community** — 全ユーザーに公開されたワークフロー（閲覧・コピー可能）
- **History** — 過去の生成物一覧
- **Jobs** — 撮影後工程の「一括実行」のジョブ一覧。見えるのは自分のジョブと、チームに共有（Team / Public）されたワークフローから投入されたジョブ。チームの owner は全件。進捗・失敗数・OK/NG の確認状況・本日の利用枚数が自動で更新される。行から「開く／キャンセル／失敗分を再実行／削除」ができる（削除は投入した本人とオーナーのみ）。ジョブ名か SKU で検索できる
- **ジョブを開くと確認グリッド** — 上のタブで列（「切り抜き」と各バリアント）を切り替え、1 列ずつ写真のカードが並ぶ（カードに元ファイル名とサイズ）。準備完了になった順にサムネイルが描かれ（保存して次回から再利用）、表示背景を白 / グレー / 市松で切り替えられる。クリックで選択、ダブルクリックか Enter で拡大して元画像と比較（左右で写真、上下で列）。各カードのチェックボックスを入れると「チェックした n 枚を再度切り抜く」（エンジンや設定を変えて、その写真だけやり直し）と「チェックした n 枚を書き出し」が出る。「すべて選択」「失敗を選択」「解除」あり。「レイアウト設定」で余白や背景を変更して全アイテムに再適用（再課金なし）。バリアント = 投入元ワークフローの Product Layout ノードで、ジョブ画面での追加・削除・変更はノードに書き戻され、キャンバス側の追加・削除もジョブに反映される。編集できるのは「そのワークフローを編集できる人」（所有者と、「チームのメンバーも編集できる」がオンのときの同じチームのメンバー）だけ。それ以外のメンバーは閲覧のみ（編集したい場合はワークフローをクローン）。「すべて書き出し」でフル解像度の ZIP

### キャンバス画面
- 左側のツールバーでノードを追加
- ヘッダー中央の **Canvas / App** トグルでモード切り替え

## ノードの種類

| ノード | 役割 |
|---|---|
| Text Prompt | プロンプト（指示文）を入力する |
| Prompt Enhancer | 入力テキストを AI が最適なプロンプトに書き換える |
| Reference Image | 参照画像をアップロードする |
| Reference Video | 参照動画をアップロードする |
| Image Generation | AI で画像を生成。参照画像を最大10枚同時使用可能 |
| Video Generation | AI で動画を生成。テキスト→動画・画像→動画・動画→動画に対応 |
| List | 複数の画像やテキストをまとめてバッチ処理に渡す |
| Camera List | カメラアングル（正面・俯瞰・斜め等）を複数指定してバッチ処理 |
| Note | キャンバス上のメモ。生成には関与しない |

生成ノードを実行すると「Image Display / Video Display」が自動で作られ、結果が表示される。

### 撮影後工程（商品写真の一括処理）
| ノード | 役割 |
|---|---|
| Batch Input | 商品写真を最大 50 枚まとめて登録（ファイル名から SKU を抽出）。★ の 1 枚だけをキャンバス上で試せる。「一括実行…」で全枚数を裏側の処理に投入する |
| Remove Background | 背景を切り抜く（BiRefNet v2 / Bria）。元画像のピクセルは変えず、マスクだけを保存する |
| Product Layout | 余白・配置・背景・影を指定して EC 用のレイアウトを作る。設定を変えても再課金なしで描き直せる |
| Batch Results | 一括結果。このワークフローから投入したジョブと、その確認グリッド（切り抜き・バリアント・生成結果）をキャンバス上で見る。チェック・拡大・再度切り抜く・書き出し・キャンセル/削除もここからできる |
| Export | ファイル名の規則・形式・容量上限を指定して ZIP に書き出す。「切り抜きの透過 PNG も書き出す」（既定でオン）で元のサイズの透過 PNG が `cutout/` に入る |

一括実行のジョブはブラウザを閉じても進み、ホーム画面の **Jobs** から状態を確認できる。

## チーム機能（支店運用）

> ここが 4月時点から最も大きく変わった部分。**すでに本番で使える**。

- **チーム = 支店**。1人のユーザーは1つのチームに所属する。
- **役割**: オーナー（複数可）とメンバー。オーナーだけが、招待・メンバー削除・役割変更・チーム名変更をできる。
- **招待リンクで参加**: オーナーが「招待リンク」を発行して渡すと、相手はそれを開くだけで参加できる（リンクは7日間有効・1本のみ）。
  - すでにアカウントがある人 → リンクを開いて「参加する」
  - **アカウントがない人 → そのリンクからその場でアカウントを作ってそのまま参加**（招待経由でのみ新規登録できる）
- **共有**: ワークフローは「非公開 / チーム内共有 / 全体公開」から選べる。チーム内共有にすると同じ支店のメンバーが見られる。
- **使用状況**: チーム設定で、今月の画像・動画の使用量（枠に対する消費）とメンバーごとの内訳が見られる。

**運営の作業はシンプル**: 運営側は「支店のチームを作り、オーナーを1人登録する」だけ。以降のメンバー追加はオーナーが招待リンクで自分たちで行える。

## 生成の利用枠（クォータ）

- 既定: 画像 **100枚** / 動画 **7本**（チームごとに設定可能）
- **チーム（支店）単位の月次管理**。個人ごとではなく、**支店に割り当てた枠をメンバー全員で共有**する。
- 毎月自動でリセット。枠を使い切ると、その月はそれ以上生成できない。
- 上限チェックはサーバー側で行われるため、回避はできない。

| 項目 | 内容 |

## 現時点の制約

- **ページリロード中の生成**: 画像生成の途中でリロードすると結果が復元されないことがある（動画は数分以内なら復元可能）。
- **リアルタイム共同編集**: 未対応。同じワークフローを複数人が同時に編集することはできない（チーム内での共有・閲覧は可能）。
- **生成物は90日で自動削除**: 長期保存が必要なものはダウンロードしておく。

## チームでワークフローを一緒に編集する（チームの編集を許可）
- 表示範囲を Team か Public にしたうえで、表示範囲メニューの「チームのメンバーも編集できる」をオンにすると、同じチームの全員がそのワークフローを編集できる（カードに「編集可」バッジ）。オフ（既定）なら他のメンバーは閲覧とクローンだけ。
- 同時に編集できるのは 1 人ずつ。所有者は開けばすぐ編集でき、メンバーは「編集する」を押して編集を始める。誰かが編集中はヘッダーに「○○さんが編集中・閲覧のみ」と出て、その人の画面は閲覧になる（編集者が保存すると 20 秒以内に取り込まれる）。
- 編集中の人がタブを閉じる・別の画面へ移る・10 分操作しない・タブを 5 分隠したままにすると編集は自動で終わる。90 秒更新が無いときは「引き継ぐ」で引き継げる。
- 名前・表示範囲・編集の許可・削除は所有者だけ。編集中に他の人の保存とぶつかった場合は上書きせず、「読み直す」か「自分の変更をコピーとして保存」を選べる。
- 編集を許可したワークフローのジョブ（確認グリッド）では、編集できるメンバーもバリアントを変更できる（キャンバスを誰かが編集中のときは保存できない）。

## 規定プロファイル（設定一式の書き出し・読み込み）
- キャンバス左の Workflows 一覧で、開いているワークフローの「…」→「プロファイルを書き出す」で、撮影後工程の設定（SKU の抽出規則・切り抜き・バリアント一覧・背景生成・書き出し）を 1 つの JSON（`<名前>.ppprofile.json`）に書き出せる。
- 「プロファイルを読み込む…」で別のワークフローに当てられる。既存のノードは残して設定を更新し、バリアントは名前で突き合わせて「更新・追加・削除」、背景生成は Text Prompt ＋ Image Generation（ジョブごと）を作ってつなぐ。当てる前に内容の確認が出る。同じプロファイルなら同じ出力になる（2 社目以降の導入はプロファイルの編集だけで済ませる土台）。
- サンプル: リポジトリの `docs/profiles/sample-ec-sns.ppprofile.json`（EC 白背景 1200×1200 ＋ SNS ストーリー 1080×1920 の生成背景）。

## 生成した背景を使う（SNS 用バリアントなど）
- Text Prompt → Image Generation（パネルの「一括実行のスコープ」を「ジョブごと」に）→ Product Layout の背景入力につなぎ、Product Layout の「背景の種類」を「画像」にする。Image Generation の結果ノード（Result）から背景入力につないでもよい。
- 一括実行では背景の生成はジョブで 1 回だけ（50 枚でも 1 回。Nano Banana 2 で約 $0.04）で、全アイテムの同じバリアントに同じ背景が使われる。投入前の確認に「ジョブごと n 件」と出る。
- 背景入力につながっていない「ジョブごと」の Image Generation、アイテムごとのスコープの背景、プロンプト無しは一括実行の対象外（投入前に注意が出る）。
- キャンバス上の Product Layout のプレビューは、背景の Image Generation を **キャンバスで Generate したとき** に背景付きになる（それまでは単色で描き、その旨の案内が出る）。一括実行の結果（Batch Results / App / ジョブ管理）はジョブごとに生成した背景を使うので、Generate を押していなくても背景付きになる。

## Apps（App 化したワークフローの一覧）と App モード
- 左のナビの **Apps** に、App モードで使えるワークフローが並ぶ。自分のものと、チームに共有されたもの。種類は 2 つ:
  - **撮影後工程**（Batch Input があるワークフロー）: App モード = 左で写真を入れて「一括実行…」、右にジョブと結果（ジョブ管理画面と同じ確認グリッド）。
  - **生成**（グループを App 化したワークフロー）: 従来の App モード。
- カードの「App で開く」で `/app/<id>` が開く（キャンバスの Canvas / App 切替でも同じ画面に入れる）。「キャンバス」はノードを見る・編集する人向け。
- 撮影後工程 App で入れた写真は **その画面だけで持ち、ワークフローには保存しない**（共有 App を使うメンバーの写真がワークフローに混ざらない）。投入したジョブには残る。SKU の規則はキャンバスの Batch Input ノードの設定に従う。
- 結果欄はキャンバスの現在の Product Layout / Export ノードの設定を見る（レイアウトを変えたい人はキャンバスで変える）。「再度切り抜く」「書き出し」「キャンセル・削除」もここからできる。
- Jobs は従来どおり、全ワークフローのジョブを横断して見る画面。

## 一括結果ノード（キャンバスでジョブの結果を見る）
- ノードメニューの「撮影後工程」から **Batch Results** を置くと、このワークフローから投入したジョブ（新しい順）が選べ、ジョブ管理画面と同じ確認グリッドがノードの中に出る。入出力ポートは無く、大きさはドラッグで変えられる。
- できること: 列タブの切替、カードのチェック、ダブルクリックで拡大、チェックした写真の「再度切り抜く」「書き出し」、すべて書き出し、キャンセル・失敗分の再実行・削除、「ジョブ管理で開く」。
- **レイアウトはキャンバスの Product Layout ノードで変える**。余白や背景を変えると、ノード内のサムネイルがその場で描き直される（fal は呼ばない・再課金なし）。Product Layout ノードを足せばバリアントの列が増える。書き出しの形式や「切り抜きの透過 PNG も書き出す」はキャンバスの Export ノードの設定に従う。
- 見えるジョブはジョブ管理画面と同じ規則（自分が投入したもの。ワークフローがチームに共有されていればチームの投入分も）。
- キーボード操作はノードの中をクリックしてから（矢印キー・Space・Enter・B）。ノードの外ではキャンバスの操作に戻る。
- App モード（撮影後工程 App）では、同じ確認グリッドが右側の結果欄になる。

## AI 処理をつなげる（切り抜き → 合成 / レタッチ → 切り抜き）
- 一括実行は、写真ごとの AI 処理を **1 経路につき 2 段まで** つなげられる（3 段目は投入前に注意が出て対象外）。
  - 切り抜き → 合成: Batch Input → Remove Background → Image Generation（切り抜いた商品だけを入力にして背景を生成・合成）。同じ Remove Background から Product Layout にもつなげる。
  - レタッチ → 切り抜き: Batch Input → Image Generation（レタッチ）→ Result → Remove Background → Product Layout。レタッチ後の写真を切り抜いてレイアウトする。
- Image Generation に写真由来の画像入力（Batch Input・Remove Background・前段の Image Generation）があれば、「一括実行のスコープ」の設定に関わらず写真ごとに実行される（ノード側でスコープが「アイテムごと」に固定される）。「ジョブごと」は画像入力の無い背景生成だけに使う。
- キャンバスでは Remove Background の出力を **Image Generation の画像入力だけ** につなげる（他のノードの画像入力にはつながらない）。Image Generation をつないだ状態で Remove Background を「実行」すると透過の切り抜き画像も保存され、Image Generation の「参照 1（切り抜き）」になる。つなぐ前に実行していた場合は Remove Background に注意が出るので「実行」でやり直す。
- 一括実行の確認ダイアログに **ノード別の内訳**（何が何回動くか・2 段なら段数）が出る。写真ごとの画像生成があるときは「枚数 × 種類 = 回数」の注意が必ず出る（生成は切り抜きより時間もコストもかかる。Nano Banana 2 の編集は 1 回 ≈ $0.04）。2 段の処理は、1 段目が終わった写真から順に 2 段目が投入される。
- ジョブ画面には **生成結果のタブ**（ノード名）が増える。レタッチ → 切り抜きのジョブでは「切り抜き」タブはレタッチ後の写真を切り抜いた結果で、拡大表示の「元画像と比較」は元の写真。
- 書き出しは生成結果も ZIP に入る（フォルダ名 = ノード名、ファイル名は `{sku}_{ノード名}_{index}`、形式は Export の指定に変換）。切り抜きの透過 PNG（元のサイズ・`cutout/{sku}_cutout_{index}.png`）は Export ノードの「切り抜きの透過 PNG も書き出す」が既定でオンなので一緒に入り、ジョブ画面の書き出しダイアログでも付け外しできる。「再度切り抜く」は切り抜きだけをやり直し、その切り抜きを入力にする生成は自動でやり直される（レタッチ → 切り抜きのジョブで、レタッチはやり直さない）。
