# ピロット導入手順書 — チームのセットアップ（運営向け）

**対象:** 複数チームを持つ toB 顧客の受け入れ（ピロット）
**所要:** 1チームあたり約5分
**前提:** チーム管理MVP＋invite-gated signup 本番稼働済み（2026-07-02〜）

---

## 0. 仕組みの前提（1分で把握）

- **チームが分離の単位**。チームごとに独立したワークスペース＋月次クォータ。チーム同士は見えない。
- **1ユーザー = 1チーム**。ユーザーは組織のメールアドレスで作る（個人利用と混ぜない）。
- **運営がやるのは「チーム作成 ＋ owner 1人の登録」だけ。**
  メンバーは owner が配る招待リンクから **アカウント作成込みで自己参加**する（運営作業ゼロ）。
- 全体の新規登録は Supabase 側でブロックしたまま。招待リンクの所持だけが登録のゲート。
- 上限: **1チーム50人**（コード定数）・招待リンクは **7日期限・1本のみ・再発行で旧失効**。

---

## 運営コンソール `/admin`（推奨・手順1〜2の代替）

**2026-07-05〜**、運営専用画面 `/admin` から**チーム＋owner を1画面で作成**できる（下記の手順1（Dashboard）＋手順2（SQL）が不要になる）。

- **前提（1回だけ）**: Vercel の環境変数 `ADMIN_USER_IDS` に**運営の user_id をカンマ区切り**で設定する（本番・staging・beta とも）。設定後に再デプロイ。
  - user_id は Supabase → Authentication → Users で自分のアカウントをクリックすると `User UID` として確認できる。
  - 未設定だと `/admin` は誰が開いても 403（フェイルクローズ）。
- **使い方**: 運営アカウントでログイン → `https://<本番URL>/admin` を開く → 「チームを追加」にチーム名・owner メール・クォータを入れて作成 → 表示される案内文を owner に送付（手順3と同じ）。全チームの今月消費・人数・owner も一覧できる。
- **既存メールで 409 が出る場合**（そのメールに既にアカウントがある）: コンソールでは作成できないため、下記「手順2の例外」の SQL で既存ユーザーを owner にする。
- 破壊操作（削除・Ban）はコンソールに無い（安全側）。従来どおり owner のメンバー管理 or Dashboard で行う。

> 以下の手順1〜3 は、コンソールを使わない場合（または `ADMIN_USER_IDS` 未設定時）の従来手順。内容は等価。

## 1. owner アカウントの作成（Supabase Dashboard）

チームの管理者（owner）1名分のアカウントを作る。

1. **本番** Supabase → Authentication → Users → **Add user → Create new user**
2. Email: 顧客担当者の**組織メールアドレス**
3. Password: ランダムな仮パスワード（**顧客に教えない**。手元で生成して捨てる）
4. **Auto Confirm User にチェック**（メール確認をスキップ）
5. 作成後、ユーザー一覧でそのユーザーをクリックし **User UID（UUID）をコピー**

> パスワードは次のステップ（案内文）で本人にリセットさせるので、共有不要。

## 2. チームの作成 ＋ owner 登録（SQL Editor・本番）

`<< >>` を書き換えて **本番 DB** の SQL Editor で実行:

```sql
-- チーム作成 + owner 登録（1チーム = 1回）
with new_team as (
  insert into public.teams (name, quota_image_monthly, quota_video_monthly)
  values ('<<会社名 チーム名>>', 100, 7)   -- クォータは月次。契約に応じて変更
  returning id
)
insert into public.team_members (team_id, user_id, role)
select id, '<<手順1でコピーした owner の UUID>>', 'owner'
from new_team
returning team_id;
```

確認（1行返り、name・quota・owner が正しいこと）:

```sql
select t.id as team_id, t.name, t.quota_image_monthly, t.quota_video_monthly, tm.user_id, tm.role
from public.teams t
join public.team_members tm on tm.team_id = t.id
where t.name = '<<会社名 チーム名>>';
```

- 複数チーム → チームごとに手順1〜2を繰り返す（**owner はチームごとに別メールが必要**。1人1チーム制約のため、同一人物が複数チームの owner にはなれない）。
- 既存アカウントの人を owner にしたい場合（例外運用）:
  `update public.team_members set team_id = '<<team_id>>', role = 'owner' where user_id = '<<UUID>>';`
  （その人の旧個人チームは空で残るが無害）

## 3. owner への案内（テンプレをコピペして送付）

> ────────────────────────────
> 【Node Canvas AI】アカウント準備のご案内
>
> 1. 下記 URL を開き、「パスワードをお忘れの方」から
>    ご登録メールアドレス（このメールの宛先）でパスワードを設定してください。
>    https://node-canvas-ai.vercel.app
>
> 2. ログイン後、左メニューの「Team」→ 右上の「メンバー管理」を開き、
>    「招待リンクを発行」→「コピー」で招待リンクを取得できます。
>
> 3. 招待リンクをチームメンバーに配布してください（社内チャット等）。
>    メンバーはリンクを開き、メールアドレスとパスワード（8文字以上）を
>    入力するだけで登録・参加が完了します。
>
> 補足:
> - 招待リンクは 7日間有効・最新の1本のみ有効です（再発行すると古いものは無効）。
> - メンバーの削除・権限変更も「メンバー管理」から行えます。
> - 生成回数の上限はチーム単位です（メンバー全員で共有）。
> ────────────────────────────

- パスワードリセットのメールが届かない場合: 迷惑メールを確認。それでも不達なら、運営が Dashboard で仮パスワードを再設定して**別経路で安全に**伝え、ログイン後に My Page から本人に変更させる。

## 5. 日常運用リファレンス

| やりたいこと | 誰が | 方法 |
|---|---|---|
| メンバー追加 | owner | 招待リンクを配布（アカウント無しでもリンクから作成・参加） |
| メンバー削除（退職） | owner | メンバー管理 → ゴミ箱。本人は新しい個人チームに戻る（本人の作成物は本人がアクセス可のまま） |
| チーム間の異動 | 本人 | 新チームの owner から招待リンクをもらい開くだけ（自動で移動） |
| owner の追加/交代 | owner | メンバー管理 → 「owner に」。最後の owner は離脱/降格できないガードあり |
| 招待リンクの無効化 | owner | 「再発行」（旧リンク即失効）。放置でも7日で失効 |
| クォータ変更 | 運営 | `update public.teams set quota_image_monthly = <<n>>, quota_video_monthly = <<n>> where id = '<<team_id>>';`（即時反映） |
| チーム名変更 | owner | メンバー管理 → 「チーム名」の鉛筆アイコンから変更（運営が SQL で変更も可） |
| 今月の消費確認 | 運営 | `select kind, sum(count) from public.usage_counters where team_id = '<<team_id>>' and period = to_char(now(), 'YYYY-MM') group by kind;` |
| メンバー別の消費 | 運営 | 上記に `, user_id` を group by に追加（UI での可視化は P1 予定） |

**アカウント自体の削除**は原則行わない（生成物・履歴への影響があるため「チームから削除」に留める）。退職者のアカウントを無効化したい場合は Dashboard の Ban user を使う。

## 6. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 招待リンクで「無効な招待リンクです」 | 失効（再発行済み）or 7日期限切れ | owner が再発行して配布し直す |
| 「このメールアドレスは登録済みです」 | 既にアカウントがある | 同画面の「ログイン」タブでログイン → 参加 |
| 「チームの人数上限に達しています」 | 50人キャップ | 不要メンバーを削除。恒常的に足りない場合は運営へ（コード定数 `MAX_TEAM_MEMBERS` の変更） |
| 「最後の owner です…」と出て離脱/降格できない | owner が1人しかいない | 先に他メンバーを「owner に」してから実行 |
| 生成がブロックされる | チームクォータ上限到達 | 消費を確認（§5）→ 必要なら上限変更。毎月1日に自動リセット（period キー切替） |
| メンバーの画像が他メンバーから見えない | 仕様（オプトイン共有） | 見せたい WF をヘッダーの可視性で「Team」にする |
| パスワード設定メールが届かない | Supabase 標準メールの制限/迷惑メール | 迷惑メール確認 → 不達なら §3 補足の代替手順 |

## 7. セキュリティ注意

- 招待リンクは「参加＋アカウント作成」の権限を持つ。**社外に共有しない**よう owner に案内。漏洩が疑われたら即「再発行」。
- 運営作業はすべて**本番** Supabase（srlhhilvjdivftbwbgxz）で行う。service role キーは共有しない。
- チームをまたぐデータ閲覧は仕様上不可（テナント分離）。「本社で全チームを見たい」要望が出たら別機能（ロールアップ・未実装）として相談。
